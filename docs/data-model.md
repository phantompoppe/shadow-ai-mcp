# Data model

`connectors` records source type, mapping version, last attempt/success, latest event timestamp, health, and sanitized error code. `connector_sync_state` holds cursor and checkpoint. `observations` holds canonical event metadata, actor/device, destination, provider, route, correlation ID, evidence URI/hash, and a deduplicating SHA-256 ID. `registry_assets` holds approved asset policy, aliases, owner, purpose, expiry, route, and risk tier. `findings` stores rule/version, status, severity, confidence, first/last seen, actor, asset, reasons, deterministic explanation, and steps. `finding_evidence` links observations and reference hashes. `detection_runs` records job status and counts. `audit_events` records tool, caller, timestamp, hashed filters, duration, count, and outcome.

Indexed columns cover event timestamps, detection ID, status, actor/device, provider/destination, MCP server ID, canonical registry endpoint/domain, and correlation ID. The Alembic migration creates all eight tables. Observation and finding JSON documents preserve typed model fields; indexed columns support bounded searches. Stable observation IDs hash source ID plus connector ID, or a canonical field tuple when source IDs are absent. Finding IDs hash detection ID and observation ID. Replays update findings without inflating occurrence count; the MVP emits one finding per triggering observation.

UTC is used for all application timestamps. Query strings, fragments, URL userinfo, long paths, and unsafe evidence URIs are discarded or redacted during normalization. Source payloads stay in the SIEM/proxy/gateway. The retention worker removes aged observations and findings with linked evidence rows. Audit events are retained by database policy; configure an external immutable export and purge schedule.
